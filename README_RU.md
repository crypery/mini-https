# Мини HTTPS-сервер

> [English version](README.md)

> [China version](README_CN.md)

Самодостаточный мини HTTPS-сервер на языке C/CPP, построенный на библиотеке **crypery HTTPS Library**. Не требует OpenSSL и других внешних зависимостей: TLS-стек, HTTPS-сервер и все утилиты собраны в одном проекте.

## Описание

Сервер принимает HTTP/1.1-запросы по TCP или TLS (HTTPS), обслуживает статические файлы из каталога `www/`, предоставляет JSON API, WebSocket и Server-Sent Events, принимает загрузку файлов (multipart) и работает с пулом рабочих потоков. Вся конфигурация задаётся в `config.json`; при первом запуске файл создаётся автоматически со значениями по умолчанию.

## Особенности

- **HTTPS без OpenSSL** - встроенный TLS-стек (TLS 1.2/1.3, AES-GCM, RSA/X25519/P-256, SHA-256, HMAC-SHA256), поддержка самоподписанных сертификатов
- **HTTP/1.1** - роутинг, статические файлы, gzip-сжатие ответов, chunked-обработка
- **WebSocket** - upgrade, text/binary-кадры, ping/pong, close
- **Server-Sent Events (SSE)** - потоковая отправка событий
- **Загрузка файлов** - multipart/form-data с сохранением в `www/upload`
- **Формы и query-параметры** - разбор `application/x-www-form-urlencoded` и `multipart/form-data`
- **JSON API** - ответы в формате JSON
- **Пул рабочих потоков** - настраиваемое количество (1-64)
- **Логирование** - в консоль, в файл или в оба; уровни DEBUG/INFO/WARN/ERROR; трансляция логов подключённым WebSocket-клиентам
- **Ограничение размера тела запроса** (`max_body_mb`, 0 - без ограничения)
- **Редирект `www` на основной домен** (`www_redirect`, по умолчанию `true`) - запросы к `www.<домен>` отвечают `301 Moved Permanently` на основной домен с сохранением схемы, порта и URI: `http://www.localhost/...` -> `http://localhost/...`, `https://www.localhost/...` -> `https://localhost/...` (только если основной домен есть в `domains`)
- **Настраиваемые таймауты** - IO, TLS-рукопожатие, accept и др.
- **Кроссплатформенность** - Windows (Winsock) и POSIX (Berkeley sockets + pthreads)

## Используемые модули

| Модуль | Назначение |
|---|---|
| `crypery` | HTTPS-библиотека: HTTP/1.1-сервер (роутинг, статика, gzip, WebSocket, SSE, multipart), TLS/SSL-стек (рукопожатие, шифрование, сертификаты) и HTTP/HTTPS-клиент |
| `utilery` | Утилиты: JSON-парсер, модуль логирования, загрузка конфигурации, UTF-8-кодек и регулярные выражения |
| `zlib` | Сжатие/разжатие gzip для HTTP-ответов |
| `compat.h` | Слой переносимости: сокеты, потоки и примитивы синхронизации для Windows и POSIX |

## Компиляция

Требуется компилятор GCC (MinGW-w64 для Windows).

### Сборка серверов

Поставляются два примера серверов:

- `server-base.c` - пример сервера со статическим сайтом: отдаёт только статические файлы из `www/` (без API / WebSocket / SSE / загрузки файлов).
- `server.c` - пример сервера со всем функционалом: статика плюс JSON API, WebSocket, SSE, загрузка файлов и разбор форм/query-параметров.

```bat
build_base.bat
```

Скрипт компилирует проект и создаёт `server-base.exe` (сервер статического сайта).

```bat
build_web.bat
```

Скрипт компилирует проект и создаёт `server.exe` (сервер со всем функционалом).

### Сборка тестового инструмента

```bat
build_test.bat
```

Скрипт собирает `http_test.exe` - тестовый инструмент, который выполняет юнит-, стресс- и фазз-тесты **против работающего сервера** (см. раздел `Тестирование (http_test.c)`). Перед запуском `http_test.exe` сервер (`server.exe` / `server-base.exe`) должен быть запущен.

## Использование

### Запуск

```bat
server.exe
:: или вариант со статическим сайтом
server-base.exe
```

Сервер читает `config.json` из текущей директории. Если файла нет - создаётся с параметрами по умолчанию.

### Основные параметры конфигурации (`config.json`)

| Параметр | По умолчанию | Описание |
|---|---|---|
| `ssl_use` | `true` | Включить HTTPS (TLS) |
| `port` | `443` | Порт прослушивания |
| `upload_dir` | `www/upload` | Каталог для загруженных файлов |
| `cert_file` / `key_file` | `localhost.crt` / `localhost.key` | Сертификат и ключ TLS |
| `max_clients` | `256` | Максимум одновременных клиентов |
| `worker_threads` | `4` | Количество рабочих потоков |
| `max_body_mb` | `0` | Максимальный размер тела запроса в МБ (0 - без ограничения) |
| `timeout_io` / `timeout_handshake` / `timeout_tls_poll` / `timeout_flight` / `timeout_accept` | - | Таймауты в миллисекундах |
| `log_file` | `server.log` | Файл логов |
| `log_output` | `2` | 0 - выкл, 1 - консоль+файл, 2 - консоль, 3 - файл |
| `log_level` | `3` | 0 - DEBUG, 1 - INFO, 2 - WARN, 3 - ERROR |
| `server_name` | `nginx/1.25.2` | Значение заголовка `Server` |
| `domains` | `{"localhost":"www","127.0.0.1":"www"}` | Разрешённые домены в виде JSON-объекта: `"домен": "путь к корневой папке"` - у каждого домена свой корневой каталог |
| `www_redirect` | `true` | `true` - 301-редирект `www.<домен>` на основной домен (схема, порт и URI сохраняются); `false` - обслуживать `www.`-хосты как обычно |

### Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/info` | Информация о сервере (аптайм, счётчики, заголовки) в JSON |
| GET | `/api/hello?name=...` | Персональное приветствие (обязательный параметр `name`) |
| GET | `/api/params?k=v` | Разобранные query-параметры в HTML |
| GET | `/ws` | WebSocket-эндпоинт (echo, ping/pong) |
| GET | `/sse` | Поток Server-Sent Events |
| POST | `/api/echo` | Возврат тела запроса в JSON |
| POST | `/api/upload` | Загрузка файлов (multipart/form-data) |
| POST | `/api/form` | Разбор формы (urlencoded или multipart) |
| GET | `/*` | Статические файлы из корневого каталога домена запроса (только это отдаёт `server-base.exe`; строки API/WS/SSE выше относятся к `server.exe`) |

> Редирект `www`: при `www_redirect: true` (по умолчанию) запрос, чей `Host` начинается с `www.`, а основной домен есть в списке `domains`, отвечает `301 Moved Permanently` на ту же схему/порт/URI основного домена.

> Корни по доменам: объект `domains` сопоставляет каждому разрешённому `Host` собственный корневой каталог, например `"test.localhost": "test"` отдаёт папку `test/` для `Host: test.localhost`, а `localhost` продолжает отдавать `www/`. Запросы с `Host` вне списка `domains` отклоняются с кодом `400`. API-маршруты также регистрируются отдельно для каждого домена: сервер в цикле регистрирует набор маршрутов для каждого домена из `config.json` через `http_route(http, domain, method, path, handler)`.

### Примеры

```bat
:: Информация о сервере
curl -k https://127.0.0.1/api/info

:: Приветствие
curl -k "https://127.0.0.1/api/hello?name=World"

:: Echo
curl -k -X POST -d "hello" https://127.0.0.1/api/echo

:: Загрузка файла
curl -k -X POST -F "file=@test.txt" https://127.0.0.1/api/upload

:: Форма
curl -k -X POST -d "a=1&b=2" https://127.0.0.1/api/form

:: Редирект www (301 на основной домен, схема/порт/URI сохраняются)
curl -k -i -H "Host: www.localhost" https://127.0.0.1/
:: -> HTTP/1.1 301 Moved Permanently, Location: https://localhost/
```

## Тестирование (`http_test.c`)

`http_test.c` - автономный тестовый инструмент, который выполняет **юнит-**, **стресс-** и **фазз-тесты** против **работающего** сервера. Он объединяет общие тесты (прогоняются против обоих серверов) и тесты `server.c` (только полнофункциональный сервер): `base` - `server-base.exe` (только статика), `web` - `server.exe` (статика + API + WS + SSE + загрузка), по обычному HTTP или по TLS. Каждая проверка печатает `[PASS]`/`[FAIL]` и полученный код статуса; в конце выводится сводка и гистограмма всех кодов ответов.

Сначала должен быть запущен сервер, а аргументы `base`/`web` и `http`/`https` должны соответствовать запущенному серверу и его `config.json`:

```bat
:: 1. Запустить сервер (в одном терминале)
server.exe            :: или server-base.exe

:: 2. В другом терминале - собрать и прогнать тесты
build_test.bat
http_test.exe <base|web> <http|https> <host> <port> [unit|stress|all]

:: Примеры
http_test.exe base https 127.0.0.1 443 all     :: server-base, TLS, юнит + стресс
http_test.exe web  https 127.0.0.1 443 unit    :: server,     TLS, только юнит
http_test.exe base http  127.0.0.1 8443 stress :: server-base, обычный HTTP, только стресс
```

### Юнит-тесты

Общие (оба сервера):

- **Статические файлы** - `GET /` и `GET /index.html` -> `200`, несуществующая страница -> `404`, `POST /` (тело игнорируется) -> `200`
- **gzip** - создаётся предварительно сжатый `www/index.html.gz`, проверяются `Content-Encoding: gzip` и магические байты `1f 8b`, затем файл удаляется
- **Ошибочные пути** - некорректный запрос, `../` (traversal) -> `400`, заблокированный путь (`config.json`) -> `403`, неизвестный поддомен в `Host` -> `404`, некорректный/пустой `Host` -> `400`, хост `www.` -> `301`-редирект, ~10 КБ заголовков -> `431`, URI длиной 3 КБ -> `414`/`404` (без падения)
- **Ограничение размера тела** - `Content-Length: 300000000` -> `413` (жёсткий предел), отрицательный `Content-Length` обрабатывается
- **Методы запроса** - маршрутизация стандартных методов (маршруты `GET`/`POST` отвечают, `PUT`/`DELETE`/`PATCH` уходят в статику -> `404` на `/api/*`, `HEAD`/`OPTIONS` -> `200`, регистронезависимый `get`) + фазз некорректных методов (пустой метод, без пути, CR/NUL/контрольные байты внутри, методы длиной 16/100 символов, CONNECT authority form)
- **Фазз сырых запросов** - мусор в `Cookie` (NUL/контрольные байты, без `=`, пустые имена, много `;`, percent-escaped UTF-8, дублирующиеся заголовки, вложенный CRLF), мусор в `Host` (поддомен 609 символов -> `404`, двоеточия/пробелы/пустой -> `400`, дублирующийся `Host` - первый выигрывает), запрос только с методом и без версии, ~8,6 КБ заголовков -> `431`, URI 4 КБ -> `404`, traversal (`..` и percent-encoded) -> `400`, absolute-form цели (`http://host/path` -> путь, неизвестный хост -> `404`), POST без `Content-Length`, отрицательный/огромный `Content-Length`, NUL-байт в URI, а после шторма - проверка здоровья
- **Устойчивость TLS** (только HTTPS) - некорректный тип/версия записи, только ChangeCipherSpec, TLS-alert, небольшие записи app-data, смешанные корректные/некорректные записи, запись >16 КБ, сформированный ClientHello; текстовый запрос на TLS-порту -> `426` или чистое закрытие (всё ограничено по времени, рабочий поток не блокируется)

Только `server.c` (web-сервер):

- **Web API** - `GET /api/info` (JSON), `GET /api/hello?name=` (приветствие) и отсутствующий `name` -> `400`, `GET /api/params` (разобранные HTML), `POST /api/echo` (echo в JSON)
- **Куки** - `GET /api/cookie/set` -> заголовок `Set-Cookie`, круговой `GET /api/cookie/get` (найден / не найден, несколько кук, `=` в значении), некорректные `Cookie`-заголовки обрабатываются, невалидные имя/значение куки -> `400`, `Cookie`-заголовок 9 КБ -> `431`
- **Формы и загрузка** - `POST /api/form` urlencoded и multipart; `POST /api/upload` multipart (файл сохраняется в `www/upload` и проверяется на диске), загрузка не-multipart -> `400`
- **WebSocket** - `GET /ws` -> `101` с корректным `Sec-WebSocket-Accept` (проверка независимым SHA-1 + base64), echo текстового кадра, кадр закрытия
- **SSE** - `GET /sse` -> `200` `text/event-stream` с событиями `connected` + `tick`

Только `server-base`:

- **Проверка отсутствия API** - `GET /api/info` и `POST /api/echo` -> `404`; любой метод отдаёт статический файл

### Стресс-тесты

- **Burst** - 12 одновременных запросов (больше, чем рабочих потоков; ловит регрессию пробуждения пула)
- **Быстрые** - 30 последовательных запросов
- **Параллельные** - 8 потоков x 10 запросов
- **Загрузка 1 МБ** - большое тело на `/api/upload` (server) или `/` (base)
- **Шторм простаивающих и разорванных соединений** - много простаивающих и резко закрытых (RST) соединений, затем проверка здоровья (сервер должен оставаться отзывчивым)
- **Slowloris-капля** - запрос отправляется по 1 байту каждые 2 секунды, чтобы фаза заголовков превысила дедлайн сервера; сервер должен ответить `408` и освободить рабочий поток
- **Неполные запросы** - частичный запрос, полные заголовки без финального `CRLF-CRLF`, только LF в конце строк: сервер должен завершить соединение за ограниченное время (чистое закрытие или статус ошибки), не вешаясь и не отвечая ложным успехом

### Вывод

Каждый тест выводит полученный код статуса: `0` - соединение не установлено, `1` - соединение есть, но статуса нет, `2xx/3xx/4xx/5xx` - код ответа сервера.
